### 2.2 oauth.go — epoch, invalidate, epoch-fenced singleflight, token-endpoint classification, scope-claim validation

- `tenantTokenSource` (oauth.go:30-41) gains `epoch uint64` and `tenantID string` (hook argument). `newTenantTokenSource` (oauth.go:71-84) gains the `tenantID` parameter — sole construction site is `NewOAuthTokenSource` (oauth.go:43-67).
- `OAuthTokenSource.Invalidate(binding)`: validate exactly like `AccessToken` (oauth.go:113-120 — `TenantSourceID` + `SourceSystem` match + binding exists); unbound/mismatched is a **no-op returning nil**. Per-tenant `invalidate()` under `mu.Lock`: `s.token = ""; s.epoch++`. Always returns nil today. **Bumps the epoch even when no token is cached** (guards the in-flight race, REQ-2). `refreshAt` is left as-is — `cachedToken`'s `token != ""` conjunct (oauth.go:150) is the authority, so the very next `AccessToken` refetches, bypassing the up-to-24 h refresh stall.
- `accessToken` (oauth.go:122-145) re-entry/epoch shape, with the sibling design's hard constraints:
  1. **`s.mu` is never held across `DoChan`/wait.** Read the epoch under `RLock`, release, then join. The flight closure's `cacheToken` takes `Lock`; an RLock held across the wait would writer-starve it into a deadlock.
  2. Key the flight `fmt.Sprintf("client-%d", epoch)` (replaces the constant `"client"`, :126). The closure **captures the keyed epoch** (never re-reads `s.epoch` — key/epoch identity is the anti-poisoning invariant), retains the existing inner `cachedToken` re-check (:127-129, unchanged — without it a caller whose entry check raced a completed flight performs a redundant HTTP fetch), and calls `fetchToken(ctx, epoch)`.
  3. **Counter-based re-entry, bounded:** `attempts := 0`; on `errEpochDiscarded` from the flight, re-enter against the current epoch at most once; a second consecutive discard returns `ErrTokenUnavailable`. Never a counterless `for errors.Is(err, errEpochDiscarded)` loop (unbounded under a sustained 401 storm). A discard implies a bump, so the re-entry key (newer epoch) can never equal the completed flight's key (deleted on completion, x/sync v0.20.0) — no self-loop.
- `fetchToken(ctx, epoch)` (oauth.go:153-173):
  - Non-200 path: read the error body bounded by `maxTokenBodyBytes` (replaces the discard at :166), then classify through the **single classifier helper set — unified with the hook-hazard companion §2.1, one signature set for both classification sites** (the earlier `classifyTokenError(status, body)` form is dropped): `tokenErrorCode(body []byte) string` (best-effort parse of `{"error":"<code>"}`; parse failure yields `""`, non-fatal) + `scopeRejectedCode(code string) bool` (`invalid_scope`/`insufficient_scope`). Status gates stay at the call sites — here **400 (C-2):** `if response.StatusCode == http.StatusBadRequest && scopeRejectedCode(tokenErrorCode(body))` → `notifyScopeRejected()` (exactly once, inside the flight, so coalesced waiters share one firing) + `fmt.Errorf("%w: HTTP %d", ErrTokenScopeMissing, response.StatusCode)`. Any other status (incl. token-endpoint 401/403), 400 with unparseable/unknown body → `ErrTokenUnavailable: HTTP %d` as today — no invalidate, no mark, no hook. Both helpers ≤ 50 lines, cyclomatic ≤ 10; the events-endpoint site (§2.4) calls the same `tokenErrorCode` on its already-drained body, so no `*http.Response`-based or status-carrying form is ever introduced.
  - Success path: decode → **scope-claim validation** (new, REQ-4, **amended — presence check, F2**): `tokenResponse` gains `Scope *string \`json:"scope"\``. **`nil` (claim absent; server may omit `scope` when identical to the request) → accepted as today.** **Non-nil (claim present)** → must contain `auditScope` (`audit:event:write`) as an exact, space-delimited token (RFC 6749 §3.3; implement with `strings.Fields` + exact equality so `xaudit:event:write` / `audit:event:write-extra` cannot pass). **A present-but-empty claim (`"scope":""`) is a rejection, not an absence** → fail closed exactly like a missing scope: do **not** cache; `notifyScopeRejected()` once; return bare `ErrTokenScopeMissing` (no HTTP status wrapper — it is not an HTTP failure; wrapped statuses are reserved for HTTP classifications). JSON `null` unmarshals to `nil` and is indistinguishable from absent → accepted; documented boundary (`null` is not a valid OAuth2 scope value; the events endpoint re-enforces scope server-side with 403 → `ErrTokenScopeMissing`). The claim value is parsed/compared in memory only and never rendered into any error or label. Then `cacheToken(wire, epoch)`.
- `cacheToken(wire, epoch)` (oauth.go:210-217): under `Lock`, **discard when `epoch != s.epoch`** (a stale pre-invalidation fetch can never repopulate the cache — no poisoned re-entry of the rejected token); on discard, `fetchToken` returns the unexported sentinel `errEpochDiscarded` instead of the token. TTL policy (24 h cap, skew) unchanged.

### 2.3 Hook safety (hook-hazard companion, adopted in full)

- `notifyScopeRejected()` with the arm/clear **pinned inside the helper**, exact order:

```go
func (s *tenantTokenSource) notifyScopeRejected() {
    hook := s.onScopeRejected
    if hook == nil {
        return
    }
    s.hookRunning.Store(true)
    defer s.hookRunning.Store(false)
    defer func() { _ = recover() }()
    hook(s.tenantID)
}
```

  Defers run LIFO: on a hook panic `recover()` runs first, then the flag clears — released on both panic and normal return. The clear is always the deferred `Store(false)`, never a non-deferred call after `hook(...)` (a panicking hook would leave the flag armed forever → permanent tenant wedge). Only composition-root-injected code is recovered; package-owned flight code stays panic-transparent (fail-closed).
- `tenantTokenSource` gains `hookRunning atomic.Bool`; `accessToken` checks it **after the cache fast path, immediately before the only join point** (cache hits remain available during a hook) and returns `ErrTokenUnavailable` when set. Guard is per-tenant-source: cross-tenant `AccessToken` from a hook is permitted (different flight — no self-join). **Collateral (documented):** the guard rejects *any* same-tenant flight join during the hook window, not only the hook's own re-entrant call — a concurrent publish in that window gets a transient `ErrTokenUnavailable` instead of coalescing. Safe: the drain's durable ladder retries, and the hook is composition-root code under a keep-it-short contract.
- Documented residuals (pathological composition-root code): a `runtime.Goexit`-ing hook runs the defers (flag cleared ✓) but v0.20.0's `errGoexit` branch skips the waiter fan-out → coalesced waiters park until their own ctx deadline — transient starvation, not a wedge; a blocking hook parks waiters for its duration, bounded by caller ctx deadlines ("keep the hook short" contract).

### 2.4 publisher.go — events-endpoint 401/403 classification + propagation

In `Publish` (publisher.go:83-97), after `client.Do`, before `validateReceipt`:

- **Transport error (amended — F1):** `response, err := p.client.Do(request); if err != nil { return fmt.Errorf("%w: transport", ErrTokenUnavailable) }`. The raw `client.Do` error is a `*url.Error` that embeds the **full events-endpoint URL** (`Post "https://…/api/v1/events?wait_for=ledgered": dial tcp …`). The wrap matches the sibling `fetchToken` path (oauth.go) exactly and makes the URL unreachable from any Go error. Drain behavior is unchanged (the raw error was already the generic bucket — neither `ErrTokenScopeMissing` nor `errAuditTenantUnbound` — and `ErrTokenUnavailable` is the same generic bucket → `pending`/`audit.publication_failed` ladder); only the error text is sanitized. This closes the last raw-error exit in `Publish`: `authorization` returns fixed sentinels, `newRequest` returns `ErrInvalidConfig`/`ErrInvalidEvent`, `validateReceipt`/`decodeReceipt` return fixed sentinels.
- `StatusUnauthorized` — **the direction delta (C-4):**
  1. Drain the body bounded by `maxReceiptBytes` (as today, :223), `Close` it (the branch replaces `validateReceipt`'s deferred close).
  2. `_ = p.tokens.Invalidate(SourceBinding{TenantID: fact.TenantID, SourceSystem: source})` — `source` is already returned by `authorization` (publisher.go:103-120). **Status-driven: runs regardless of whether the body parses.**
  3. Best-effort parse the drained body with the **same `tokenErrorCode` helper** (single classifier signature, §2.2 — this site passes its `maxReceiptBytes`-bounded drained bytes; no synthetic `*http.Response` is constructed): `scopeRejectedCode(tokenErrorCode(body))` → `fmt.Errorf("%w: HTTP %d", ErrTokenScopeMissing, 401)`. **Mutually exclusive with `ErrTokenRejected`.** No connector hook fires for events-endpoint responses (C-C: the alert is the service-side counter, REQ-4/REQ-5). Body-parse failure is non-fatal → the plain path below.
  4. Otherwise → `fmt.Errorf("%w: HTTP %d", ErrTokenRejected, 401)` (replaces the opaque `audit governance: HTTP 401`, :224).
  - No retry loop inside `Publish` — the drain's durable ladder (callback_audit.go) is the redelivery mechanism; the refetched token serves the retried attempt.
- `StatusForbidden` — sibling C1 scope (merged plan §3): `MarkBindingUnhealthy(binding)` (cache retained, cooldown), return `ErrTokenScopeMissing: HTTP 403`. **No `Invalidate`, no connector hook.** Present in this design's surface only as the routing input for §2.5.
- `authorization` (publisher.go:113-117) — **C-B propagation (load-bearing):** `if errors.Is(err, ErrTokenScopeMissing) { return "", "", err }` before the generic collapse; token-empty/CRLF guard stays. Without this the token-endpoint classification is unreachable through `Publish` and REQ-4's alerting cannot fire.
- `validateReceipt` (:220-245) byte-unchanged (202-only, conflict-as-success per the tree baseline, idempotency key `fact.ID.String()` — REQ-5: refetch/redelivery does not disturb governance dedup).

3. **Integration compile gate:** `staticTokenSource` (internal/service/callback_integration_test.go:64-73) must gain the new methods in M1, or `make test-integration` fails to compile — invisible to the default gate. The gate is `make check-integration-compile` (`go test -tags integration -run '^$' ./... && go vet -tags integration ./...`); `go build -tags integration` is **inert** (never compiles `_test.go`).

7. **Baseline pinning:** the tree's uncommitted conflict-as-success (`validateReceipt`), the `audit_ledger.go` loop removal (sole-`Publish`-caller precondition), the claim-based dispatch, and the untracked `callback_integration_test.go` are the behavioral baseline (M0 commits them). 11. **Leakage invariants (amended — F1/F2/F3).** (a) No raw `http.Client` error escapes either HTTP path: the token path wraps `%w: transport` (shipped) and the events path now does the same (§2.4) — no endpoint URL can appear in any Go error. (b) `tokenResponse.Scope *string` is a presence check; explicit-empty fails closed (§2.2). (c) The four forbidden payload classes — token material, OAuth2 error/scope code strings, endpoint URLs, tenant IDs — reach **no** new error text (errors carry only fixed sentinels plus `HTTP %d` statuses; body contents are parsed in memory and never echoed), **no** audit fact (`FinishPublication` persists only fixed `error_code` strings; `redactAuditPayload` strips token/bearer/secret keys; the classification itself writes no fact), and **no** metric label (the only new label is `source` = `strings.TrimSpace(fact.Source)`/`SourcePrefix`, allow-listed to `snaplink|aero-im|aero-vault|aero-id` plus the FM-14 `""` case, `%q`-rendered; the hook closure ignores its tenantID argument). The tenant ID reaches only the in-process hook argument (composition-root code), never any error, fact, or label.

## 4. Failure modes

| # | Scenario | Behavior | Design guard |
|---|---|---|---|
| FM-1 | In-flight fetch (epoch e0) completes after `Invalidate` bumped to e1 | `cacheToken(wire, e0)` sees `e0 != s.epoch`, discards; e0 waiters get `errEpochDiscarded` → re-enter once against e1, coalescing into the fresh flight | `cacheToken` Lock-guarded epoch compare is the authoritative anti-poisoning guard (REQ-2); hard constraint #3's counter bounds re-entry |
| FM-2 | Concurrent 401s from N publishes | N `Invalidate`s are idempotent; epoch monotonic; all post-invalidation callers join the latest key → at most one fetch per distinct epoch key; a spread-out storm may start intermediate refetches that later invalidations discard — harmless | epoch-keyed `DoChan`; T-10.2.1 (N = 8, `/token` == 2) |
| FM-3 | 401 storm (repeated invalidations) | Re-entry bound of one; second consecutive discard → `ErrTokenUnavailable`; drain ladder (8 attempts) bounds total work; no livelock | counter-based re-entry (REQ-2, §2.2); `TestSecondConsecutiveDiscardIsTerminal` |
| FM-4 | Composition-root hook panics | Without recover-wrap: x/sync v0.20.0 re-raises in a fresh goroutine → process crash + waiter starvation. Residual: `runtime.Goexit`-ing hook → transient starvation to ctx deadline (not a wedge); blocking hook parks waiters for its duration | `notifyScopeRejected` arm/clear + defer-recover, exact order pinned §2.3 |
| FM-5 | Hook calls `AccessToken` for the same tenant (self-join) | Without guard: parks on its own in-flight flight forever → permanent tenant outage. Guard failure mode: non-deferred clear after a panic leaves the flag armed forever → permanent tenant wedge | `hookRunning` atomic check at the join point; arm/clear pinned inside `notifyScopeRejected` |
| FM-6 | Events-401 with scope-missing body (persistent) | `Invalidate` + `ErrTokenScopeMissing` → settlement `pending`/`audit.binding_unavailable` forever, re-probing each retry; **never dead-letters**; exactly one `ObserveAuditScopeMissing` per failed attempt → operator alert while the condition persists | §2.4 delta + §2.5 routing (branch precedes `maxAttempts`); T-10.2.3/T-10.1d |
| FM-7 | Events-401 with unparseable/empty body (persistent) | `Invalidate` + `ErrTokenRejected` → generic ladder → `dead_letter` at cap 8; the refetch self-heals a revoked token; DLQ is the correct terminal | §2.4 plain path; body-parse failure non-fatal; pinned at connector level by T-10.1/T-10.2.3 negatives and at **drain level** by `TestDrainPlain401SettlesPublicationFailed` (§6) |
| FM-8 | `Invalidate` for unbound tenant / mismatched `SourceSystem` | No-op, nil (mirrors `AccessToken` validation) | validation before lookup (§2.2); `TestInvalidateUnboundAndMismatchedBindingAreNoOps` |
| FM-9 | ~~singleflight retains last result per key~~ — premise false at v0.20.0 | `doCall` deletes the key on completion; no retained last result; no `Forget` needed | **Process gate, no dedicated test** (correctly premise-false): implicitly exercised by T-10.2.2 Part 1 — the stale e0 result is *dropped* (never served), which is only observable because no retained last result exists to be joined; source contract x/sync v0.20.0 `doCall` delete-on-completion |
| FM-10 | Token-endpoint error body unparseable, unknown code, or status ≠ 400 (incl. 401/403 with a scope body) | `ErrTokenUnavailable: HTTP %d`; no hook, no invalidate, no mark (400-gate, C-2; sibling FM-4 boundary) | `tokenErrorCode` best-effort parse + `scopeRejectedCode` predicate, 400-gate applied at the call site; pinned by `TestScopeClassificationNegatives` (§6) |
| FM-11 | Interface commit without `staticTokenSource` update | `make test-integration` compile break, invisible to the default gate and to `go build -tags integration` | `make check-integration-compile` in M1/M5 gates and the done gate |
| FM-12 | `Invalidate` lands with a non-merged signature | Compile conflict with sibling campaigns on merge | §3.1 fixed-once interface — **process gate, no behavioral test is possible**: `var _ TokenSource = (*OAuthTokenSource)(nil)` compile assertion (§6 regression row) + M1 ≡ C1 joint-commit discipline + M6 zero-edit verification |
| FM-13 | Successful token response's `scope` claim omits `audit:event:write`, is differently formatted, or is explicitly empty (`"scope":""`) | Token not cached; `ErrTokenScopeMissing`; hook exactly once; publications pend at `binding_unavailable` with an alert — fail-closed, operator-visible; explicit-empty is a rejection, not an absence (F2) | `Scope *string` presence check (§2.2); no silent proceed |
| FM-15 | Events endpoint unreachable (transport error) | `ErrTokenUnavailable` wrapped `%w: transport`; generic ladder → `dead_letter` at cap — settlement identical to today, error text sanitized (no URL) | §2.4 transport wrap (F1); `TestPublishTransportErrorNeverLeaksEndpointURL` |
| FM-14 | `fact.Source` empty/whitespace at the counter site | `strings.TrimSpace` yields `""` → metric labeled `source=""` | REQ-5's TrimSpace; label convention §2.6; **T-10.1d (1)/(4)** pins label == `strings.TrimSpace(fact.Source)` plus the whitespace-source variant labeling `source=""` |
