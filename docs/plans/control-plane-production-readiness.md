## First increment design

### Request fingerprints

- Persist a versioned SHA-256 digest with the authoritative Operation/Sync row in its existing audited transaction.
- Bind verified actor/tenant/issuer/subject/client, target, command type and normalized payload. Dataset selections are sets; workflow steps retain their order.
- Check the digest on normal replay and on the unique-insert race recovery path. Return a sanitized dotted conflict code for a changed request.
- Historical rows have no verified original client binding: reject key reuse conservatively and retain their GET/list/reconciliation paths. Never silently generate a second command.
- Durable resource creation bypasses the generic HTTP response cache so cached responses cannot hide payload conflicts or changed authorization. Legacy response caching remains compatible.

### Data lifecycle barrier

- Serialize writes with the authoritative account row, check disposition while locked, and keep one lock order with erase.
- Valid late source events must have an explicit durable disposition; no poison-event success acknowledgements and no unbounded retries.
- An erased account cannot be restored by source version, summary, direct upsert, projection replay or a stale replica.
- Preserve existing download rejection; separately cover export capture/storage races and approved minimal retention/Legal Hold.

### Export completeness

- Honor the normalized submitted dataset selection, never an implicit all-snapshot read.
- Traverse source and membership keyset pages with item/byte/cursor bounds; fail rather than silently truncate.
- Report selected scope, counts, per-source freshness and explicit completeness. This is a local projection export, not a global source snapshot or Vault blob export.

### Increment 3 — original-artifact recovery and local download fencing

Checkpoints reject changed keys/digests/sizes and retain original result metadata.
- Recovery/download validates durable artifact identity, request scope, content digest and identical job/artifact expiry. JSON decoding preserves large integer versions and rejects trailing content; plaintext budgets account separately for encryption overhead.
