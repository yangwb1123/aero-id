## 2. Design: the shipped single-delivery architecture (frozen)

The delivered design has five load-bearing decisions, all shipped and tested. This document freezes them; no new API is introduced.

**D-1 — Append-only ledger, drain-only delivery (REQ-1).** `AuditLedgerService.Record` appends the fact and its `status='pending'` `audit_publications` row in one transaction (`appendInTx`, `repository/audit_ledger.go:120-140`) and performs zero deliveries. Governance delivery and callback enqueue happen exclusively in the worker's `drainPublications` → `publishAuditFact` (`callback_audit.go:87-105`), which first enqueues callback deliveries (`enqueueFact`, deduped by `OnConflict DoNothing`) and then fans out to governance publishers. The composition root (`wireAuditServices`, `app/audit.go:65-86`) fails closed with panics if the publication repo or publishers cannot be attached to the callback service.

**D-2 — Lease-based at-least-once with fencing (REQ-5).** `ClaimPublication` atomically (single tx, `FOR UPDATE SKIP LOCKED`) claims up to 50 rows (`pending` due, or `delivering` with expired lease) with a lease bound to a per-instance unique worker ID. The lease window is **DB-clock-only (M-1)**: the claim predicate and `lease_until = now() + interval` both use the database clock, so cross-instance clock skew cannot re-claim a still-live lease and a backward NTP step cannot stall claims; `next_attempt_at` scheduling stays app-clock (never a fencing decision). The lease is **sized to the workload (M-5)**: `lease = max(5m, 2 × 50 × PublicationTimeout / WorkerConcurrency)` (`publicationLease`, `callback_audit.go`), where `PublicationTimeout` is the governance publisher timeout (derived from the existing `audit_governance.timeout` config, no new key), so a slow batch serialized through the shared bulkhead can never outlive its own lease. The **attempt counter moves only at committed finish (M-4)**: `ClaimPublication` never touches `attempt`; `finishPublicationAttempt` computes `item.Attempt + 1` (this delivery attempt's number) and `FinishPublication` persists it in the same lease-guarded UPDATE, so crash/claim/hydration cycles that never published cannot inflate the counter into a premature terminal `dead_letter`. `FinishPublication` is lease-guarded (`status='delivering' AND lease_owner=?`); `RowsAffected != 1` yields `ErrAuditPublicationLeaseLost`. A failed finish (raw DB error or lease lost) is observed on the finish-failure metric, never retried inline; the row stays `delivering` and is re-claimed after lease expiry — retry, never duplicate, outcome counted only on committed finish.

**D-3 — Bulkhead-bounded drain (REQ-2).** The fan-out acquires one `internal/pkg/bulkhead` slot per publication (capacity `Callback.WorkerConcurrency`, serial when ≤ 0, max 64). A slow governance endpoint cannot starve callback deliveries beyond the shared bound. Bulkhead loss loses no correctness state — leases and receipts live in PostgreSQL.

**D-4 — In-transaction audit for callback and hold mutations (REQ-4).** `CreateSubscriptionWithAudit` / `DeleteSubscriptionWithAudit` / `ResetDeliveryWithAudit` / `PutHoldWithAudit` / `RemoveHoldWithAudit` append the fact via `AppendInTx` inside the same transaction as the business row; rollback removes ledger row + publication row together. Duplicate facts fold via `ErrAuditDuplicate` (dedupe key `(tenant_id, source, event_id)`); the fold is an error-checked branch, not a `_ =` swallow (see R-2).

**D-5 — Fail-closed swallow gate (REQ-3).** `make check-audit-swallow` scans `internal/service` with P1 + P2 patterns, self-tests against positive fixtures containing the historical swallow shapes, and must be green at exactly 0 live matches. It is part of the done gate (AGENTS.md).

## 3. Compatibility constraints

- **Public behavior preserved.** Audit endpoints, callback registration/deletion/replay, and hold endpoints keep their exact request/response contracts. `ErrAuditDuplicate` maps to success at the service layer (`Record`), preserving idempotent-retry semantics for clients.
- **At-least-once is the delivery contract.** Consumers must be idempotent; exactly-once is achieved via dedup receipts (`OnConflict DoNothing` on `callback_deliveries`, lease-guarded finish, dedupe key on the ledger) — never assumed from the transport.
- **Config unchanged.** `callback.worker_concurrency` (bulkhead capacity), `callback.max_attempts`, `callback.retry_base`, `audit_governance.*` (flag-gated publishers, tenant bindings). A `0` value means code default. The drain lease is derived from the already-existing `audit_governance.timeout` (`CallbackConfig.PublicationTimeout`, M-5) — no new config key.
- **Gate scope is deliberate.** P1 covers `_ =` swallows of Record/Log/Publish/FinishPublication/ClaimPublication; P2 covers bare Record/Log/FinishPublication/ClaimPublication calls. Bare `Publish` is intentionally excluded from P2 (best-effort SSE hub, `notification.go`), and the dead tree is never scanned. These exemptions are load-bearing and must not be widened silently.
- **No second delivery path.** Any new audit consumer must hook into the drain path (`publishAuditFact`) or the callback enqueue — never a direct `Publish` from a request handler or from `Record`.
- **Migrations immutable.** No schema change is part of this direction; existing `audit_ledger`/`audit_publications`/`callback_deliveries` DDL is untouched.

## 4. Failure modes and handling

| # | Failure | Detection | Behavior | Recovery |
|---|---|---|---|---|
| FM-1 | Claim tx fails (DB outage, schema mismatch) | `ObserveAuditPublicationClaimFailed("claim_tx", err)` — phase label on `aero_control_audit_publication_claim_failed_total{phase="claim_tx"}` | The claim tx rolls back atomically — no partial claim, no row stranded `delivering`; facts pend with no attempt (M-4: claim never increments `attempt`) | Next tick retries the claim; persistent failure is alertable (claim-failed counter, phase `claim_tx`) |
| FM-12 | Post-claim fact hydration fails (FM-1 split, second phase) | `ObserveAuditPublicationClaimFailed("fact_hydration", err)` with the wrapped `repository.ErrAuditPublicationFactHydration` | The claim tx **committed** (every row in the batch is `delivering`), but per-row fact hydration outside the tx (`audit_publication.go`) failed partway. `ClaimPublication` returns the hydrated prefix alongside the error; the drain delivers the prefix this tick and the remainder re-claims after lease expiry — `attempt` untouched (M-4), no premature dead_letter | Watch `{phase="fact_hydration"}` rate; the stranded `delivering` rows clear within one lease window (≤ sized lease). A persistent hydration error means ledger reads are failing (DB outage) — the same alert as FM-1, distinguishable by phase |
| FM-2 | Publish fails (governance endpoint down) | publisher error → `publicationOutcome` | Row → `pending` with backoff `next_attempt_at`; **retry budget consumed only at committed finish** (M-4): the incremented `attempt` is persisted by the same lease-guarded UPDATE that settles the row, so crash/claim/hydration cycles that never published consume nothing | Re-claim on next due tick; `dead_letter` at max attempts |
| FM-3 | Tenant binding unavailable | `errAuditTenantUnbound` | Row → `pending` with `audit.binding_unavailable`, no attempt consumed; the binding pre-filter runs **before the publisher loop** (`publishAuditFact`), so with multiple publishers an unbound tenant can never let earlier publishers already publish (duplicate publishes on every retry) | Retried with delay; ops must fix binding coverage (startup check `validateAuditBindingCoverage` also fails closed) |
| FM-4 | Finish fails — raw DB error | `ObserveAuditPublicationFinishFailure(status, err)` | Row stays `delivering`; outcome NOT counted | Lease expiry → re-claim (same worker or another) → re-publish → commit; outcome counted once (`TestFinishPublicationRawDBErrorNotCountedUntilCommitted`) |
| FM-5 | Finish fails — lease lost (another worker reclaimed, or lease expired mid-flight) | `ErrAuditPublicationLeaseLost`, same metric | No inline retry, no double-finish (lease-guarded UPDATE) | Next claim re-asserts lease ownership and re-delivers |
| FM-6 | Duplicate event (client retry, replay) | `ErrAuditDuplicate` | Service maps to nil; in-tx fold after domain write | No orphan rows; retried domain write is a no-op-equivalent re-apply |
| FM-7 | Context cancelled mid-drain | `bulkhead.Acquire` error → loop `break` | Already-claimed-but-unprocessed items stay `delivering` until lease expiry | Re-claimed next tick; at-least-once preserved, no correctness loss |
| FM-8 | Publication repo/publishers never wired (future regression) | `wireAuditServices` panic at startup; runtime `ObserveAuditPublicationDrainSkipped` if guard bypassed | Process fails closed at boot; facts pend, never silently dropped | Fix composition root; drain-skipped counter is the runtime signal |
| FM-9 | Callback enqueue partially succeeds then publisher fails | retry of `enqueueFact` | `OnConflict DoNothing` dedups re-enqueues | No duplicate `callback_deliveries` rows across attempts |
| FM-10 | Multi-instance lease contention | `FOR UPDATE SKIP LOCKED` + per-instance worker ID | Rows partitioned across instances; a crashed instance's leases expire and are re-claimed | Fencing by unique worker ID; no two active finishers for one row |
| FM-11 | Poison/oversized payload | redaction + 64 KiB cap at `Record` (`redactAuditPayload`) | Fact payload truncated with sha256 marker | Chain integrity preserved; consumers reject unsupported versions to quarantine. **Caveat (M-6): aero-id-side fact-schema validation does not exist at drain** — facts carry no `schema_version` column, `publishAuditFact` marks a row `completed` on nil publisher error regardless of fact content, and the only local quarantine is `dead_letter` on publisher error. `completed` is only as strong as the publisher's own validation; poison accepted by a permissive publisher is acknowledged as applied |
| FM-13 | Drainer crash / panic mid-batch (M-2) | instance death or a panicking publisher (no `recover` in the drain goroutines — fail-closed but process-wide); outcome metric skipped for the in-flight batch | Crash windows: after claim before publish → rows stay `delivering` until lease expiry, then re-claimed (attempt untouched, M-4); after publish before finish → re-delivery of the already-published fact (at-least-once; callback receipts dedupe via `OnConflict DoNothing`; duplicate governance publish is contractual); after finish commit → nothing to re-do, dedup receipts fold the re-delivery | Restart (systemd/k8s restarts the pod); lease-expiry re-claim resumes the batch within one lease window; alert on instance death + `{status="completed"}` outcome rate to see the duplicates |

## 5. Migration steps

**Data/schema: none.** This direction introduced no migration; `audit_ledger`, `audit_publications`, `callback_deliveries` and their indexes are unchanged.

**Operational rollout (for deployments predating `90c4c24`):**

1. Deploy the binary; the drain worker starts claiming `pending` rows automatically (every instance runs `callbackSvc.Start`, `internal/app/new.go:166`; claims are partitioned across instances via `FOR UPDATE SKIP LOCKED`). Rows left `delivering` by an old process with an expired lease are re-claimed on the first tick after lease expiry (≤ one lease window: the sized lease, `publicationLease` — 5 min under default config).
2. Verify no old process still holds leases. Owners are per-instance `callback-<uuid>` worker IDs (`callback.go:87`) and are not mapped to pods in logs, metrics, or health output — identify them by age, not by name:
   ```sql
   SELECT lease_owner, min(updated_at) AS first_claimed_at, count(*)
     FROM audit_publications
    WHERE status = 'delivering'
    GROUP BY lease_owner;
   ```
   After the rollout window (one 5-min lease + one drain tick), every `first_claimed_at` must be at or after the deploy timestamp. A still-running old process re-claims rows too, so this verifies ownership convergence, not absence of old processes — stop pre-rollout processes to be sure.
3. Confirm gate in CI: `make check-audit-swallow` is part of the done gate (AGENTS.md); it needs no Docker and must stay at 0 matches.
4. Wire alerting on the control-plane metrics. All five counters are **per-process in-memory**: they reset on process restart, are never persisted, and a series line only appears once its counter is non-zero. Alert rules MUST aggregate across instances — use `sum(...)` over a `rate(...)` window (Prometheus `rate` handles counter resets); never alert on a bare single-instance counter value. `/metrics` is served unauthenticated on the main HTTP router (`GET /metrics`, Prometheus text format 0.0.4, `internal/handler/http/router.go:77`); scrape every instance.

   | Emitted series (exact name as scraped) | Meaning | Alert (aggregated) |
   |---|---|---|
   | `aero_control_audit_publication_claim_failed_total{phase="claim_tx"}` | A drain cycle whose `ClaimPublication` tx rolled back; nothing was leased (FM-1) | `sum(rate(aero_control_audit_publication_claim_failed_total{phase="claim_tx"}[5m])) > 0` |
   | `aero_control_audit_publication_claim_failed_total{phase="fact_hydration"}` | A drain cycle whose claim tx committed but post-commit fact hydration failed partway; hydrated prefix delivered, remainder re-claims after lease expiry (FM-12) | `sum(rate(aero_control_audit_publication_claim_failed_total{phase="fact_hydration"}[5m])) > 0` |
   | `aero_control_audit_publication_finish_failures_total{status="..."}` | `FinishPublication` failed (raw DB error or lease lost); row stays `delivering`, re-claimed after lease expiry | `sum(rate(aero_control_audit_publication_finish_failures_total[5m])) > 0` |
   | `aero_control_audit_publication_outcomes_total{status="completed\|pending\|dead_letter"}` | Committed settlements; `dead_letter` is terminal governance non-delivery after `MaxAttempts` | `sum(rate(aero_control_audit_publication_outcomes_total{status="dead_letter"}[5m])) > 0` |
   | `aero_control_audit_publication_drain_skipped_total` (no labels) | Drain ran with the publication repo unwired (wiring regression; facts pend silently) | `sum(rate(aero_control_audit_publication_drain_skipped_total[5m])) > 0` |
   | `aero_control_audit_ingest_failures_total{source="..."}` | Durable audit append failed (fail-closed 503 path) | `sum by (source) (rate(aero_control_audit_ingest_failures_total[5m])) > 0` |

   **Dashboards (decision: Postgres SQL datasource — no new gauges).** The publication-status distribution and a "per-partition ledger lag" are NOT exported by the binary: the control-plane registry has no publication-status gauge and no ledger-lag gauge (`internal/pkg/metrics/control_plane.go:81-93`). Adding gauges would require new registry fields, a periodic reporter in the drain worker, and tests — code surface this design otherwise freezes at zero. Instead, query the authoritative `audit_publications` table directly from a Grafana Postgres SQL datasource (columns per migration `000045`; both shapes are index-covered by `idx_audit_publications_due (status, next_attempt_at, id)`):
   - Status distribution:
     ```sql
     SELECT status, count(*) AS rows
       FROM audit_publications
      GROUP BY status;  -- pending / delivering / dead_letter / completed
     ```
   - Delivery lag ("per-partition ledger lag" has no shipped meaning: the ledger is appended synchronously inside the request transaction, so there is no write lag to measure; the actionable lag is how long facts stay unsettled):
     ```sql
     SELECT count(*) AS backlog
       FROM audit_publications
      WHERE status IN ('pending','delivering') AND next_attempt_at <= now();
     ```
     ```sql
     SELECT extract(epoch FROM now() - min(next_attempt_at)) AS oldest_unsettled_age_seconds
       FROM audit_publications
      WHERE status IN ('pending','delivering');
     ```
5. Runbook:
   - **`dead_letter` rows have no requeue API in the shipped binary.** The only replay surface, `POST /v1/audit/replays`, re-executes source commands and creates NEW facts → NEW publication rows; it never resets an existing `dead_letter` row. Interim recovery is a direct UPDATE on the authoritative row (maintenance window; the drain observes the reset on the next tick, default `worker_interval` 1 s):
     ```sql
     UPDATE audit_publications
        SET status = 'pending', attempt = 0, error_code = '', next_attempt_at = now()
      WHERE id = '<publication-id>' AND status = 'dead_letter';
     ```
     Verify: the row is claimed and settles `completed`, or re-dead-letters after `MaxAttempts` (watch `aero_control_audit_publication_outcomes_total{status="dead_letter"}`). A dedicated `RequeuePublication` surface + `cmd/audit-replay` is designed separately (`docs/plans/2026-08-07-dead-letter-replay-requeuepublication-design.md`, pending implementation); the SQL above is the interim procedure until it lands.
   - A persistent `pending` with `error_code = 'audit.binding_unavailable'` means governance tenant bindings are missing. Fix `audit_governance.bindings` (a config key validated at startup — there is no `audit_governance` DB table) and restart; `validateAuditBindingCoverage` (`internal/app/audit.go`) fails boot while durable tenant state is uncovered. This failure is only reachable when `audit_governance.enabled: true` (default `false`: with no publishers built, no `binding_unavailable` rows can be produced).

## 7. Residual risks and optional hardening (not required for this direction)

Rev-2 closeout: the reliability review's M-1 (DB-clock lease), M-4 (attempt only at committed finish), M-5 (lease sized to worst-case batch latency), FM-1 (claim-failed metric phase split + hydration-gap prefix delivery), and FM-3 (tenant-unbound pre-filter) are **resolved in code with tests** (see §6 closeout row). The remaining residuals:

- **Escalation for unbounded publishers (M-5 boundary).** The sized lease assumes every publish is bounded by `audit_governance.timeout` (a hard HTTP client timeout in the connector). If a future publisher allows unbounded latency, `publicationLease`'s 2× margin no longer covers the batch and **per-item lease refresh becomes mandatory** (a `RefreshPublicationLease` repo method fenced by `(id, status='delivering', lease_owner)`, called per item before publish). Not needed today; the invariant to preserve is: lease ≥ 2 × worst-case batch latency.
- **Dead-letter replay and retention (M-3) are designed, not yet implemented.** The interim recovery is the guarded SQL re-queue in §5 step 5; the product-grade `RequeuePublication` surface + `cmd/audit-replay` + purge invariants are designed in `docs/plans/2026-08-07-dead-letter-replay-requeuepublication-design.md` (pending implementation). Completed-row retention/cleanup for `audit_publications` (delivery state only; the ledger is authoritative) is covered by that plan's purge section — no cleanup exists in the shipped binary.

Verified green today, but the spec's "zero delta" conclusion does not cover these four; each is a deliberate, documented exception or a latent exposure:

- **R-1 — Dead-tree swallow sites remain (verified unreachable).** Exactly six `_ = s.audit.Log(...)` sites (dead-tree `domain.AuditLogger`): `internal/file/service_share.go:45,75`, `internal/block/block.go:66,86`, `internal/comment/service.go:431`, `internal/message/service.go:289`; `internal/domain/audit.go:17` is a comment, not a site. Composition-root proof at HEAD `13e4676`: the only `func main()`s are `cmd/server` and `cmd/migrate`; `cmd/*` imports only `internal/app` + `internal/config` + `internal/pkg/*`; `internal/app` imports only live layers (service, repository, handler, hub, outbox, connector, sso, storage, event, idempotency, middleware, region, config, pkg) — and `go list -deps ./cmd/server` / `./cmd/migrate` contain **0** of `internal/{file,block,comment,message,notification,search,audit}`. The only importers of the swallow-bearing packages are other dead-tree packages (`internal/search/{search.go,handler_grpc.go}` ← file/comment/message; `internal/notification/dispatcher.go` ← block); the dead `internal/search` gRPC server has no callers — `internal/app/grpc.go:68` registers the live `internal/handler/grpc/search.go` backed by `service.SearchService`. The sites are absent from both binaries' package graphs, so no composition root can reach them at compile or runtime. Exempt while unwired; **any future wiring of that tree must convert these sites first** — the gate will not catch them (it scans only the live layer).
- **R-2 — In-tx `ErrAuditDuplicate` fold is an explicit swallow exception.** `CreateSubscriptionWithAudit`/`DeleteSubscriptionWithAudit`/`ResetDeliveryWithAudit` (and hold WithAudit paths) intentionally fold `ErrAuditDuplicate` inside the transaction (contract §4.2, "defensive parity"). It is an error-checked branch, not a `_ =` assignment, so the gate correctly ignores it; it can never mask a failed domain write because the append runs after the domain write in the same tx. Documented here so a future reviewer does not "fix" it into a hard error and break retry semantics.
- **R-3 — Non-atomic fallback tails in `audit_hold.go:67-73,112-115`.** Reachable only when a repository lacks the WithAudit surface (unit-test-only today; the concrete repo always implements it). The fallback appends the fact after the business commit — a split-brain window. Optional hardening: fail closed (panic or error) when the WithAudit surface is absent, removing the fallback.
- **R-4 — Gate scope is `internal/service` only; extension assessed.** Measured P1+P2 matches at HEAD `13e4676`: **0** in `internal/repository`, `internal/app`, `internal/handler`, `internal/hub`, `internal/outbox`, `internal/connector`, `internal/event`, `internal/middleware`, `internal/idempotency`, `internal/region`, `internal/storage`, `internal/config`, `internal/domain`, `internal/pkg`; the only whole-tree non-dead matches are **3 false positives** in `internal/sso/client.go:335,342,346` (`c.breaker.Record(false|true)` — a circuit-breaker method, not an audit write), so a blanket whole-`internal/` extension is NOT safe without an exclusion. `errcheck` is not a viable replacement: the live tree deliberately swallows non-audit errors (`_ = s.finishJob(...)` in `sync_audit_export.go:30,40,67,72,84`, plus `defer Close`/`_ = w.Write` classes), so errcheck would need a large maintenance-prone exclusion list and would flag behavior the audit gate must keep allowing; the audit-specific P1/P2 patterns already encode exactly the audit-write surface with self-tests. **Recommended hardening (concrete):** (a) fix `scripts/check-audit-swallow.sh` to iterate all positional args (today `ROOT="${1:-...}"` silently scans only `$1` — a multi-root Makefile invocation alone does nothing); (b) extend the Makefile invocation to `bash scripts/check-audit-swallow.sh internal/service internal/repository internal/app` (0 matches measured — gate stays green at 0 with zero false positives; `internal/handler internal/outbox internal/hub` may be appended, also 0); (c) do not scan `internal/sso` without a documented `c.breaker.Record` exclusion. **API-freeze enforceability:** the swallow gate cannot enforce "ledger service must never gain a publisher surface" — a well-handled `if err := ledgerSvc.Publish(...)` passes P1/P2 by design (P2 deliberately excludes `Publish` for the SSE hub). Enforce with a reflection test instead: pin `AuditLedgerService`'s method set to exactly `{Record, Log, List, VerifyChain}` (e.g. `TestAuditLedgerServiceSurfaceFrozen` reflecting over `(*AuditLedgerService)(nil).Elem().NumMethod()` and comparing the sorted names), which breaks loudly on ANY new method, including a publisher surface, and runs in `make test`. No such test exists today; `TestAuditLedgerRecordEnqueuesOnly` proves behavior (never publishes) but does not pin the interface shape.
