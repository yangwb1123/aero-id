# 安全审查报告：aero-id 服务

## 范围

本审查涵盖了 aero-id 代码库 `main` 分支（包括所有 `internal/` 包、配置、迁移和部署清单）。通过代码检查、架构分析以及对认证、授权、输入验证、密码学、会话管理、数据保护和威胁建模的检查进行。

## 发现结果

### 发现 1：[严重] SSO 令牌撤销窗口 — 缓存使撤销的令牌保持有效

| 字段 | 描述 |
|-------|-------------|
| 类别 | 认证 |
| 严重性 | **严重** |
| 标题 | 令牌缓存为撤销的令牌创建了可预测的有效窗口 |
| 位置 | `internal/sso/token_cache.go` (第 33-48 行), `internal/sso/client.go` (第 136-143 行) |
| 描述 | 令牌缓存存储 `token → uid` 映射，TTL 为可配置的上限（默认：60 秒）。此外，`staleFor` 窗口（默认：300 秒）允许在 SSO 宕机时提供过期的身份信息。如果用户在 SSO 中被撤销，他们缓存的令牌会一直保持有效，直到缓存 TTL 到期 **并且** 过期宽限期到期——总共最多 360 秒（6 分钟）的撤销后有效窗口。 |
| 攻击场景 | 管理员撤销了流氓用户的 SSO 会话。攻击者有最多 6 分钟的时间继续使用他们缓存的令牌进行 API 调用，在此期间 aero-id 不会向 SSO 验证令牌。 |
| 影响 | 已撤销的身份在长达 6 分钟内仍可用于所有 API 调用，包括写入操作（发送消息、上传文件、分享内容）。 |
| 建议 | (1) 减小默认的 `token_cache_ttl` 和 `stale_ttl`（例如，分别设为 10 秒和 30 秒）。(2) 添加一个 **强制撤销端点**：`POST /v1/admin/revoke-tokens`，清除特定 uid 的令牌缓存。(3) 对于高安全性的写入操作，考虑绕过缓存并进行实时 SSO 验证。 |
| 工作量 | M（1-3 天） |

### 发现 2：[严重] HTTP/gRPC 服务器缺少入站 TLS

| 字段 | 描述 |
|-------|-------------|
| 类别 | 密码学 / 数据保护 |
| 严重性 | **严重** |
| 标题 | 服务间和客户端-服务通信以明文形式进行 |
| 位置 | `internal/app/new.go`（第 232-258 行），`configs/config.yaml`（整个服务器部分） |
| 描述 | HTTP 和 gRPC 服务器都没有 TLS 配置。config 结构体缺少 `tls_cert_file`/`tls_key_file` 字段，所有传输均以纯文本形式进行。只有 **出站** SSO 连接有 TLS 配置。这意味着密码、令牌、文件和元数据都以明文形式在线传输。 |
| 攻击场景 | 一个位于同一网络段（例如，VPC 中的另一个 pod）的攻击者可以嗅探所有流量，捕获认证 Bearer 令牌、私人消息内容和文件上传/下载。 |
| 影响 | 所有数据机密性和完整性都受到损害。能够通过网络路由的任何人都可以拦截或修改请求/响应。 |
| 建议 | 向 `ServerConfig`/`HTTPConfig`/`GRPCConfig` 添加 TLS 配置（`cert_file`、`key_file`）。在服务器初始化时加载证书。对于生产环境，使用反向代理（Envoy、nginx、ALB）处理 TLS 终止，但服务器应支持直接 TLS。 |
| 工作量 | M（1-3 天） |

### 发现 3：[高] 不支持 HTTP cookie 的 CSRF 保护

| 字段 | 描述 |
|-------|-------------|
| 类别 | 会话管理 |
| 严重性 | **高** |
| 标题 | 缺少 CSRF 保护（当使用基于 cookie 的 SSO 令牌时） |
| 位置 | `internal/handler/http/router.go`（整个文件），`internal/middleware/auth.go`（第 21-36 行） |
| 描述 | HTTP 处理程序依赖 `Authorization: Bearer <token>`，但没有实现任何 CSRF 保护。如果 aero-id 被部署为从设置 HTTP cookie 的同一域提供服务的 SSO，那么攻击者的网站就可以触发跨站请求。CORS 默认情况下通过 `Access-Control-Allow-Origin: *` 允许所有来源，这放大了攻击面。 |
| 攻击场景 | 1. 用户登录 SSO → 设置了会话 cookie。2. 用户访问 `attacker.com`。3. 页面中的 JavaScript 向 `aero-id.example.com/v1/messages` 发出 `POST` 请求。如果 cookie 被发送（取决于 SameSite 设置），则该请求会被认证。 |
| 影响 | 如果与基于 cookie 的 SSO 部署结合，则可能导致 CSRF 攻击；可能导致用户在不知情的情况下发送消息、上传文件或更改权限。 |
| 建议 | (1) 实现 CSRF 令牌（每个会话的 `X-CSRF-Token` 标头）。(2) 配置 `SameSite=Strict`/`Lax` cookie 属性（在 SSO 端）。(3) 锁定 CORS 来源——永远不要在生产环境中使用通配符 `*`。(4) 检查自定义 `X-Requested-With` 标头。 |
| 工作量 | M（1-3 天） |

### 发现 4：[高] 预签名下载 URL 不可绑定用户

| 字段 | 描述 |
|-------|-------------|
| 类别 | 授权 |
| 严重性 | **高** |
| 标题 | 文件下载 URL 仅受静态 HMAC 密钥保护，不进行用户绑定 |
| 位置 | `internal/storage/local.go`（第 85-110 行），`internal/storage/signing.go`（整个文件） |
| 描述 | HMAC 签名仅对 `key|expires` 进行签名。它不包含任何用户标识符（uid、session_id）。任何拥有有效 URL 的人都可以下载该文件。由于 URL 有效期长达 5 分钟，因此它可以在接收者之间共享，而无需通过授权系统。 |
| 攻击场景 | 1. 用户 A 请求 `GET /v1/files/:id/url`，获得一个有效期 5 分钟的 URL。2. 用户 A 在公共聊天中分享此 URL。3. 任何拥有该 URL 的人都可以在 5 分钟内下载该文件，即使他们没有被授权。 |
| 影响 | 预签名 URL 的共享超出了预期的授权范围。接收者可以转发 URL。 |
| 建议 | 将 `uid` 包含在 HMAC 有效载荷中：`hmac(key, uid + "|" + storageKey + "|" + expires)`，然后在 DownloadURL 中创建一个绑定到特定 uid 的 URL。在验证时，也断言 `uid` 与经过认证的 actor 匹配（或者对于匿名共享，接受 `uid` 参数）。 |
| 工作量 | M（1-3 天） |

### 发现 5：[高] ILIKE 搜索回退可能会泄露数据

| 字段 | 描述 |
|-------|-------------|
| 类别 | 数据保护 / 威胁模型 |
| 严重性 | **高** |
| 标题 | 基于 ILIKE 的搜索回退允许暴力字符提取 |
| 位置 | `internal/repository/message.go`（第 371-395 行），`internal/repository/file.go`（第 234-262 行），`internal/repository/comment.go` |
| 描述 | 当全文搜索返回零结果时，`SearchMessagesLike`、`SearchFilesLike` 和 `SearchCommentsLike` 使用 `ILIKE '%query%'` 作为 CJK 文本的回退。此模式匹配可以逐字符枚举以提取数据：攻击者可以搜索 `%a%`、`%b%` 等来探测内容是否存在。搜索范围基于 actor 的可见性范围（消息的参与者、文件的所有者），因此泄露仅限于 actor 有权访问的内容。 |
| 攻击场景 | 1. 用户 A 与用户 B 有一条消息“我的暗号是菠萝”。2. 用户 B 使用 `SearchMessagesLike` 发送查询。3. 用户 B 执行二进制搜索：`%菠%` → 命中；`%菠萝%` → 命中。4. 用户 B 逐字符推断出“菠萝”。 |
| 影响 | 在 actor 的可见性范围内，通过搜索功能进行数据提取。仅限 ILIKE 模式，因此效率低下，但在规模上可行。 |
| 建议 | (1) 限制 ILIKE 回退的速率（每用户每分钟最多 10 次调用）。(2) 对 ILIKE 搜索添加最小查询长度（例如，≥3 个字符）。(3) 审计 ILIKE 搜索的查询模式以检测爬取行为。 |
| 工作量 | S（< 1 天） |

### 发现 10：[中] 令牌以纯文本形式存储在进程内存中

| 字段 | 描述 |
|-------|-------------|
| 类别 | 数据保护 |
| 严重性 | **中** |
| 标题 | Bearer 令牌在 TokenCache 中作为 Go map 键以纯文本形式存储 |
| 位置 | `internal/sso/token_cache.go`（第 17-31 行） |

### 发现 12：[中] SSE 连接没有重新认证

| 字段 | 描述 |
|-------|-------------|
| 类别 | 会话管理 |
| 严重性 | **中** |
| 标题 | 事件流连接只认证一次；令牌撤销后仍保持打开状态 |
| 位置 | `internal/handler/http/events.go`（第 35-77 行） |
| 描述 | SSE `GET /v1/events` 端点只检查连接设置时的令牌。如果令牌在流的生命周期内被撤销，SSE 连接在底层 TCP 或 HTTP 连接关闭之前仍然保持打开状态。一个被撤销的用户仍然可以接收实时通知。 |
| 攻击场景 | 管理员撤销了一个用户。该用户有一个活跃的 SSE 流。在他们断开连接/重新加载之前，他们继续接收有关新消息和评论的实时通知。 |
| 影响 | 通知继续流向一个被撤销/被禁用的账户，直到连接自然结束。 |
| 建议 | (1) 将令牌 TTL 添加到 SSE 连接：每 60 秒发送一次注释 ping 并重新验证缓存中的令牌。(2) 在 `Hub` 中添加一个 `Revoke(uid)` 方法来强制终止流，在撤销/禁用时调用。(3) 设置 HTTP `Keep-Alive` 超时并结合定期重新认证。 |
| 工作量 | S（< 1 天） |

## STRIDE 威胁建模

## 最终总结

| 指标 | 值 |
|--------|-------|
| **整体安全态势** | ⚠️ **需要改进** |
| **发现总数** | 14 |
| **严重** | 2 |
| **高** | 4 |
| **中** | 6 |
| **低** | 2 |

### 最严重的 3 个问题（按紧迫性排序）

1. **[严重]** 令牌缓存撤销窗口（发现 1）——对任何会话撤销场景都是直接的权限滥用。
2. **[严重]** 缺少传输 TLS（发现 2）——所有数据在网络上以明文形式传输。
3. **[高]** ILIKE 搜索回退数据提取（发现 5）——允许 actor 在其可见性范围内逐字符提取受保护的内容。

### 顶级速赢方案（高影响力，低工作量）

| # | 发现 | 修复 | 工作量 |
|---|---------|------|--------|
| 1 | 发现 7：速率限制关闭 | 默认启用速率限制（`rps: 20, burst: 40`） | S |
| 2 | 发现 8：审计日志记录最佳努力 | 记录审计失败；添加指标 | S |
| 3 | 发现 9：默认配置中的弱凭据 | 添加启动时检查，检测默认值 | S |
| 4 | 发现 5：ILIKE 搜索泄漏 | 为 ILIKE 搜索添加最小查询长度（≥3 个字符）和速率限制 | S |
| 5 | 发现 6：CORS 允许所有来源 | 将 `cors_origins` 添加到配置并验证 | S |

### 安全债务

| 领域 | 债务 | 影响 |
|--------|------|--------|
| 认证 | 令牌撤销延迟长达 6 分钟 | 在存储 SSO 可撤销令牌的环境中无法接受 |
| 密码学 | 入站传输无 TLS；预签名 URL 用户绑定缺失 | 需要基础设施来处理 TLS 终止 |
| 审计 | 静默丢弃审计日志 | 违反 SOC2/PCI-DSS 审计完整性要求 |
| 速率限制 | 默认关闭 | 对 DoS 攻击开放；需要操作员启用 |
| 监控 | SSE 连接无硬令牌超时 | 撤销后会话仍然存在 |

---

**总体评估**：aero-id 拥有设计良好的授权模型（服务层强制执行所有权检查）、对 SQL 注入的参数化查询以及稳固的 SSO 集成模式。然而，在 **传输安全**、**令牌撤销及时性**、**审计可靠性** 和 **DoS 防护** 方面存在重大差距——对于生产环境来说，这些都是严重的问题。上述速赢方案应在部署到任何面向用户的环境之前实施。应优先考虑传输 TLS（发现 2）和令牌撤销（发现 1）的架构性修复。
